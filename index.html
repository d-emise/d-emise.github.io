introduction

welcome to the demise scripting docs. this guide is here to show you how to write custom lua scripts to hook into the demise overlay, draw screen visuals, or build your own menu layouts.

the executor runs local lua 5.4 inside our rendering engine. since demise is an external cheat, it doesn't touch or inject into game memory directly. instead, it runs in a transparent window overlaid on top of your game, which keeps things much safer.

heads up: lua is case-sensitive. aimbot.enabled works, but Aimbot.Enabled will give you a nil error. since the entire api is lowercase, write all your code in lowercase.

how to run your first script:

  1. open the cheat menu and click on the lua tab.
  2. type: print('hello from demise') in the editor window.
  3. click the execute button.
  4. look at the console tab at the bottom to check the output logs.
errors: if your code breaks, check the console. it will tell you the exact line number where the script failed (like attempt to index a nil value). read the error, it usually tells you exactly what you messed up.

render loop

if you just execute a normal script, it runs once from top to bottom and stops immediately. to draw a crosshair, keep an esp box tracked on players, or show an interactive window, your code has to run continuously.

we use on_render to register a callback function that runs every frame (60+ times a second) when the overlay updates.

on_render(callback_function)

registers your function to run every frame. the cheat automatically clears the old callback whenever you click execute again, so you don't pile up background loops.

critical concept: variable scope
if you define a variable inside your render function, it gets reset to its starting value 60 times a second. to keep track of counters, states, or toggles, you must define them outside the render loop.

bad vs good examples:

don't do this (resets count to 0 every single frame):

-- wrong way:
on_render(function()
    local count = 0
    count = count + 1
    draw_text("count: " .. tostring(count), 50, 100, color.fromRGB(255, 255, 255))
end)

do this instead (retains value correctly):

-- right way:
local count = 0
on_render(function()
    count = count + 1
    draw_text("count: " .. tostring(count), 50, 100, color.fromRGB(255, 255, 255))
end)
performance warning: do not write heavy loops or recursive lookups inside on_render. searching the entire game tree every frame will lag the overlay frame rate. keep your render loop clean.

drawing api

the drawing api lets you paint 2d graphics directly on the screen overlay. coordinates start at (0,0) in the top-left corner of your display monitor. x goes right, and y goes down.

colors use the rgb/rgba format: color.fromRGB(r, g, b, [a]) where each channel is a value from 0 to 255. alpha a is optional and defaults to 255 (fully solid).

available drawing functions:

function arguments description
draw_line x1, y1, x2, y2, color, [thickness] draws a line between two screen points. thickness defaults to 1.0.
draw_rect x, y, w, h, color, [thickness] draws a hollow box outline at (x,y) with width w and height h.
draw_rect_filled x, y, w, h, color draws a solid filled box. useful for custom backgrounds.
draw_circle x, y, radius, color, [segments], [thickness] draws a circle outline. use 32 or 64 segments so it looks round.
draw_text text, x, y, color, [size] draws text. size is a float scale (default is 13.0).

example: drawing a center crosshair

this script grabs the screen size, finds the center, and draws a small custom crosshairs overlay:

on_render(function()
    local w, h = get_screen_size()
    local cx, cy = w / 2, h / 2
    local green = color.fromRGB(0, 255, 66)
    
    -- draw cross lines (horizontal & vertical)
    draw_line(cx - 8, cy, cx + 8, cy, green, 1.5)
    draw_line(cx, cy - 8, cx, cy + 8, green, 1.5)
end)

imgui ui

imgui is an immediate-mode ui library. unlike standard ui where you create elements and keep state references, immediate-mode ui is declared and redrawn from scratch every single frame inside your render callback.

if the code runs, the widget displays. if it doesn't, it vanishes. this makes scripting menus incredibly fast.

how widgets return data:

  • imgui.button("label"): returns true only on the frame it is clicked.
  • imgui.checkbox("label", state): returns the new state (boolean). you must assign this back to your toggle variable to update it.
  • imgui.slider_float("label", val, min, max): returns the new float value.
  • imgui.slider_int("label", val, min, max): returns the new integer value.
state saving: remember to store variables outside the render loop so they don't reset when the ui checks them every frame.

imgui functions:

  • imgui.begin_window(name): starts a new window container. returns true if open.
  • imgui.end_window(): closes the current window container. must match begin.
  • imgui.text(label): prints a simple string in the window.
  • imgui.same_line(): places the next widget next to the current one on the same line.
  • imgui.separator(): draws a clean separation line.

example: custom cheat control window

this script pops up a custom gui window that lets you toggle and scale cheat settings on the fly:

local aim_state = false
local fov_value = 100.0

on_render(function()
    imgui.begin_window("my test menu")
    
    -- capture the returns to update variables
    aim_state = imgui.checkbox("toggle aimbot", aim_state)
    fov_value = imgui.slider_float("fov setting", fov_value, 20.0, 300.0)
    
    -- write directly to the cheat variables
    aimbot.enabled = aim_state
    aimbot.fov = fov_value
    
    imgui.separator()
    imgui.text("current aimbot state: " .. tostring(aimbot.enabled))
    
    imgui.end_window()
end)

cheat vars

you can read or write internal cheat settings directly using global tables. this lets your custom scripts toggle features or tweak settings dynamically.

aimbot variables:

variable type description
aimbot.enabled boolean toggles aimbot on or off.
aimbot.aim_type integer 0 for mouse, 1 for silent aim.
aimbot.hitbox integer target part index (0 head, 1 torso, etc.).
aimbot.hitchance float hit probability percentage (0.0 to 100.0).
aimbot.prediction boolean toggles aim prediction for moving targets.
aimbot.fov float size of the aimbot fov circle in pixels.
aimbot.smoothing_value float mouse movement damping / smoothing.
aimbot.target_name string (read-only) name of the currently targeted player.
aimbot.has_target boolean (read-only) returns true if locked onto someone.

esp variables:

  • esp.enabled (boolean): master visual switch.
  • esp.box (boolean): toggles 2d box outline.
  • esp.name (boolean): toggles player name tags.
  • esp.distance (boolean): toggles distance logs.
  • esp.health_bar (boolean): toggles health indicators.
  • esp.chams (boolean): toggles filled player outlines.
  • esp.skeleton (boolean): toggles skeleton bone lines.
  • esp.tracers (boolean): toggles screen-bottom tracers.

movement variables:

  • movement.fly (boolean): toggles fly mode.
  • movement.fly_speed (float): fly velocity multiplier.
  • movement.noclip (boolean): toggles character clipping.

example: hotkey toggle for fly mode

this script checks if you press the f key and toggles fly mode on or off instantly:

local fly_state = false
local was_pressed = false

on_render(function()
    local is_pressed = is_key_down(0x46) -- 0x46 is the 'F' key
    
    -- detect the key down edge transition
    if is_pressed and not was_pressed then
        fly_state = not fly_state
        movement.fly = fly_state
        print("fly toggled: " .. tostring(fly_state))
    end
    was_pressed = is_pressed
end)

roblox sdk

the roblox sdk wraps physical game objects (parts, workspaces, characters) as lua instances. the main entry point is the global object game.

instance properties:

  • inst.name (string): name of the instance.
  • inst.class (string): the exact engine class type (e.g. "Part", "Model").
  • inst.parent (instance): parent object.
  • inst.children (table): array of child instances inside this object.
  • inst.position (vector3): 3d workspace coordinate (only if it's a part/model).
  • inst.is_valid (boolean): returns false if the object has been destroyed or unloaded.
crash prevention: roblox instances are dynamically created and destroyed. trying to read properties or call methods on an invalid instance will throw a script error or crash the overlay. always verify inst.is_valid first!

finding child elements:

  • inst:find_first_child(name): returns direct child matching the given name.
  • inst:find_first_child_of_class(classname): returns first child matching the class name.

casting instances with `as_humanoid()` / `as_player()`

when you fetch generic instances from the game tree, they do not expose specific properties (like player character models or humanoid health states) by default. you must explicitly cast them first:

local hum_inst = char:find_first_child_of_class("Humanoid")
if hum_inst and hum_inst.is_valid then
    -- cast the generic instance so you can access health
    local humanoid = hum_inst:as_humanoid()
    print("npc health: " .. humanoid.health)
end

utility functions

handy functions for viewport translations, keystroke queries, and local player references.

get_screen_size()

returns the width and height of the display monitor in pixels.

local w, h = get_screen_size()

world_to_screen(vector3)

translates a 3d coordinate from the game world into a 2d screen point. returns a vector2. if the coordinate is behind the camera view, it returns negative pixel positions.

local point_2d = world_to_screen(part.position)
if point_2d.x > 0 and point_2d.y > 0 then
    -- draw on screen position
end

is_key_down(vk_code)

returns true if the key is held down. uses standard virtual key codes:

custom esp guide

here is a step-by-step guide to writing a custom esp overlay script for NPCs or specific items (like cash boxes, weapons, etc.).

step-by-step breakdown:

  1. fetch the Workspace instance from game using game:find_first_child("Workspace").
  2. loop through its children using the children table.
  3. check if the child's class is a Model (which includes player models and NPC models) or a Part (for items).
  4. find its child part representing its physical location (like HumanoidRootPart or the main part).
  5. convert its 3D position to 2D screen coordinate using world_to_screen.
  6. check if it is on screen (x > 0 and y > 0) and draw graphics using draw_circle or draw_text.

complete npc esp script:

on_render(function()
    local local_player = get_local_player()
    local local_char = local_player.character
    
    -- get workspace
    local workspace = game:find_first_child("Workspace")
    if not workspace or not workspace.is_valid then return end
    
    -- traverse all workspace objects
    for i, child in ipairs(workspace.children) do
        -- make sure it's an NPC/player model, and not our own local character
        if child.class == "Model" and child.address ~= local_char.address then
            local humanoid = child:find_first_child_of_class("Humanoid")
            local root_part = child:find_first_child("HumanoidRootPart")
            
            -- make sure target has a humanoid and root position part
            if humanoid and root_part and root_part.is_valid then
                -- translate 3D position to 2D screen coordinate
                local pos_2d = world_to_screen(root_part.position)
                
                -- draw only if the target is visible on your screen
                if pos_2d.x > 0 and pos_2d.y > 0 then
                    -- draw green ESP circle overlay
                    draw_circle(pos_2d.x, pos_2d.y, 8, color.fromRGB(0, 255, 66), 32, 1.5)
                    
                    -- draw text showing name and health
                    local health = humanoid:as_humanoid().health
                    local label = child.name .. " (" .. math.floor(health) .. " hp)"
                    draw_text(label, pos_2d.x - 30, pos_2d.y - 25, color.fromRGB(255, 255, 255), 11.0)
                end
            end
        end
    end
end)
